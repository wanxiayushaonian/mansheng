内容站点的测试重点不在 UI 组件，而在构建脚本：数据契约错了，全站都是错的。

## 优先级

1. **build.mjs 的快照测试**：固定 vault fixture，断言 graph.json 的节点数、边数、backlinks 结构
2. **数据契约测试**：每个 posts/<id>.json 必须有 html/outgoing/backlinks 字段
3. **UI 只测交互关键路径**：过滤面板、wikilink 跳转

```js
const graph = JSON.parse(await readFile('public/data/graph.json'));
assert(graph.nodes.length >= 30);
assert(graph.edges.some(e => e.kind === 'tag'));
```

## 不测什么

不测 Markdown 渲染的像素级结果（交给 markdown-it 的上游测试），不测 d3-force 的具体坐标——布局是随机的，[[typescript-类型体操]] 里的类型定义已经保证了形状正确。构建性能回归的监测归 [[前端性能预算]] 管。
