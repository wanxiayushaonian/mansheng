RSC 的核心不是「在服务端渲染」，而是「组件树分成两个世界」：服务端组件离数据近、零客户端 JS；客户端组件离交互近、按需水合。

## 一个判断框架

- 这段 UI 需要事件处理或浏览器 API 吗？→ 客户端组件
- 只是数据的静态呈现？→ 留在服务端
- 两者交界用 props 传可序列化数据，像 API 边界一样设计

## 与本站的关系

本站是纯静态 SPA，没用 RSC。但它的思想影响了数据层设计：构建时把能算的都算好（坐标、HTML、反链），客户端只取所需——这和 [[react-19-新特性]] 的 use() 数据流是同一个哲学。[[前端性能预算]] 里首屏 < 150KB 的目标，本质也是 RSC 思想的静态版。
