vault 到 500 篇后全量构建开始变慢。增量构建的核心是：以文件 mtime + 内容 hash 做缓存键，只重新解析变化的 Markdown。

## 注意点

- 文章变了，它的 **backlinks 对象** 也得重算——反链是全局依赖
- 布局坐标用旧 graph.json 做初始值，见 [[vite-构建优化]]
- 缓存文件放 `.cache/build-data.json`，记得加 .gitignore

```js
const key = `${f}:${stat.mtimeMs}:${hash(raw)}`;
if (cache[f] === key) return cacheResult[f];
```

## 效果

全量 800ms → 增量 60ms（单篇改动）。图数据的边表重建很便宜，因为 [[markdown-解析管线]] 已经把解析和关系抽取分离了。下一步想做 watch 模式热更新，那是 [[构建缓存策略]] 要展开的话题。
